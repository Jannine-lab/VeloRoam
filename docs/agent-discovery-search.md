# 骑行想法的扩展检索

主题类骑行需求（如沿江、沿湖）在首次检索时组合用户原词、关联词、已匹配路段属性和可识别的地点类别。模型可标记 `lookup.expand`，也可调用 `search_expanded_candidates`；当模型遗漏明确的沿江、沿河或沿湖主题时，后端会从用户原话保守恢复。明确避开的主题不作为正向检索。普通具名地点继续使用原有名称查找。

原词匹配、关联词匹配、数据库属性或类别匹配分别标注依据，依次排序并结合标签与距离；候选按稳定 ID 去重，危险路段和已知避让标签被排除。关联词只是模糊查询线索，不能证明实际地理关系或体验。默认范围为搜索中心 50 公里，用户明确的附近范围及候选类型会传递到“更多”；指定区域无法解析时不替换成当前位置。部分检索失败会提示结果可能不完整。

“更多”使用已展示候选 ID 去重，最多保留 200 个已展示 ID，候选选择上下文仍限 12 个；数据库每个检索词有数量上限，不保证覆盖所有结果。确认候选前仍会按 ID 重新读取，确保候选当前有效。关联词生成或搜索失败时保留可用结果，不将失败宣称为无匹配。

真实附近范围取决于提供的位置来源，IP、地图中心和定位均会通过搜索中心描述区分。关联检索使用数据库记录中的名称、属性和位置，不能证明江景、道路安全或设施可用性。扩展检索属于信息收集，不会自动选中关联候选或更改用户已确认的路线条件。

## 结构化路段搜索

Agent 可通过 `search_segments` 组合名称检索词、用户明确指定的区域、1–50 公里搜索半径、单条路段记录距离、平均坡度、爬升、最低评分、参与/收藏/骑行次数、必须匹配和希望避让的路段标签，并按评分、热度、距离、爬升或到中心的距离排序。每页最多 20 条，offset 最多 200；工具结果包含 total、hasMore 和查询说明。区域由地图服务解析为中心点，半径按路段起点直线距离计算，不是行政区边界。

筛选在数据库中先于排序和分页执行，SQL 结构、列和排序选项由服务端控制，输入值使用参数绑定。数值缺失不能满足相应筛选；避让标签未知不等于安全。`distanceKm` 是计算出的轨迹里程，筛选使用数据库记录的 `recordedDistanceKm`，两者可能不同。关联名称只表示检索线索，不证明地理位置或路线体验。该工具不执行模型生成的 SQL；结构化路段结果的“更多”沿用原筛选条件并加载下一页；其他结果的“更多”仍用于关联词扩展搜索。

## 意图理解中的地点和路段证据

综合的名称检索、关联词检索和附近检索会分别向 Agent 提供 `places` 与 `segments`，每类最多返回 8 条，并保留兼容的 `candidates`。返回的数量仅表示本次有限候选，不是数据库全量统计；某一类候选较多不会挤掉另一类。地点数据来自 `hot_points` 的 active 记录，包含类别、坐标及可用的地址、行政区和骑行相关评分；地点评分和路段评分不是同一个指标。

`search_places` 可单独按用户位置或已核实区域、模糊名称词、地点类别、半径、排序与分页检索地点，结果返回总数和数据范围说明。关键词是检索线索而非地点事实，指定区域按中心点与直线半径计算，不等于行政边界；未命中本地地点不代表地图上不存在。用户要求同时查找两类候选时，Agent 可调用综合检索或分别调用地点和路段工具。

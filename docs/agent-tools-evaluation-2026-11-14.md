# Agent 骑行工具冒烟评测（2026-11-14）

## 范围与结果

本次将 `search_nearby_candidates`、`plan_cycling_route` 和 `find_enroute_segments` 接入工具协议。使用 DeepSeek `deepseek-chat` 与合成候选、固定路线结果做小样本评测，Prompt 版本 `idea-2026-11-14.v5`。

- 附近路段查询：重复 3 次，3 次均调用 `search_nearby_candidates`。
- 确认后规划并探索沿途：重复 3 次，3 次均依次调用 `plan_cycling_route` 和 `find_enroute_segments`，每次各执行一次。
- 旧业务抽样：距离、热门偏好、具名检索、多途经顺序、候选选择 5 个场景通过，共 6 轮、18 项断言；此项仍使用固定检索数据和规划器。
- 实际数据源连通性：用固定测试坐标，只读查询附近数据库并请求一次高德骑行导航；附近工具返回成功，导航服务返回一条候选。未执行真实模型和真实地图组合的完整端到端规划评测。
- 后端自动化测试：158 项通过；另完成 TypeScript 类型检查。

首次冒烟评测时，模型在附近查询场景没有选择工具。调整提示和明确附近查询时的工具调用要求后，重新测得上述结果。真实模型抽测后，控制器补充了“模型返回回答模式时仍展示附近候选卡片”的处理，该处理由自动化测试验证。

## 局限

每个新工具场景只有 3 次重复，不能用作稳定性或线上成功率指标；候选和规划结果为合成数据，不能说明真实路线的风景、道路质量、实际骑行体验或全链路响应时间。真实地图和数据库仅做连通性检查。规划与沿途工具的超时不会中止已发出的底层地图请求，控制器会复用已启动的规划，避免重复发起。

可用以下命令复测工具选择，输出文件必须不存在：

```sh
cd VeloRoam-api
npm run eval:agent-tools -- --repeat=3 --output=/private/tmp/agent-tools-smoke.json
```

该评测需要配置 DeepSeek 密钥，会消耗模型调用额度。原始评测数据使用合成位置与固定候选，不包括真实用户骑行数据。

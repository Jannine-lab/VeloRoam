# Agent 通用地域、路段与点位检索设计

状态：设计方案，尚未接入线上对话或路线规划。本方案适用于任意受数据和地图服务覆盖的地域、路段名称及点位，不维护针对某个示例的特殊判断。

## 目标

让用户用自然语言表达“找什么、在哪里找、接下来做什么”，Agent 能先使用真实数据检索，再基于结果继续对话或规划路线。用户可以先了解候选、选择其中一项，再沿用先前预算和偏好规划。

默认从当前位置出发并在当前位置结束；用户明确声明时覆盖。只有目标里程、未指定范围时沿用 ±10% 规则，明确的距离或时间上下限优先。

## 当前实现的缺口

- 对话控制器的 `answer` 分支可以直接输出模型文字；区域内有哪些路段等事实问题需要先检索，不能只依靠模型记忆。
- 已有路段名称 `LIKE` 查询，但搜索范围由一个中心点和固定经纬度范围决定；名称不一致、跨区域长路段和地名被识别为普通地点时容易遗漏。
- 区域解析主要调用地点输入提示，将区域当成单个坐标。行政区、线路走廊与单个地点需要不同的空间表达。
- 前端历史的推荐摘要主要保存名称，后续选择时缺少稳定候选 ID，可能再次按文字搜索，匹配到其他结果或搜索失败。
- 目前自动环线主要围绕单个候选站点组装；无匹配路段时，尚不能保证在目标区域内形成符合要求的本地环线。

## 通用流程

```text
理解用户请求与历史
  → 判断：回答一般问题 / 查找候选 / 基于候选规划 / 调整已有路线
  → 识别区域、地点、路段、类别和它们在需求中的作用
  → 解析地理范围，并搜索真实路段、点位和可用地点
  → 根据名称、地域、标签、距离和约束排序，保留来源与不确定性
  → 返回真实候选或继续规划；将已展示候选的稳定 ID 写入会话上下文
  → 用户选择时复用 ID，恢复预算及偏好，再读取最新真实记录规划
  → 验证区域经过方式、连通性、实际总距离与时间
```

模型负责自然语言理解、产生可能的检索词和解释已有证据；检索、身份校验和距离计算由工具完成。模型生成的别名或扩展词仅用于检索，不作为地理事实，也不直接确认两个地点或路段相同。

## 意图与实体

为每个提及记录实体类型及作用，允许模型表达不确定并由检索结果消歧：

| 实体 | 可能作用 |
| --- | --- |
| 地域 | 候选搜索范围、需要进入的区域、区域内骑行范围、避开范围 |
| 路段或线路走廊 | 搜索对象、必须骑行的真实路段、用户选择的已有候选 |
| 点位或点位类别 | 起点、终点、途经点、补给类别、避开地点 |
| 候选引用 | 明确名称、候选 ID、序号、这个、那个、刚才推荐的 |
| 预算与偏好 | 目标及上下限、标签偏好、明确限制、途经顺序 |

同一消息可以同时包含“查询候选”和“之后规划”的目的；不因为预算或偏好尚未完整就阻止可独立执行的事实检索。规划时仅补问仍缺少且会影响规划的预算或体验。已明确的热门、休闲或训练偏好直接复用。

模型输出建议包含 `action`、`entities[]`、`searchTerms[]`、`selectedCandidateId` 和完整需求摘要。`action` 可为 `search`、`plan`、`choose_candidate`、`modify_route`、`answer`、`clarify`；只输出一个动作不足以表达复合请求时，可附带 `nextAction`。这些字段由服务端验证，不能凭模型生成的候选 ID 直接信任其存在。

## 多源检索

### 地域解析

1. 将地名解析为带来源的候选区域或地点；行政区域优先使用行政区标识与边界，单点地点使用坐标与明确的附近搜索范围。
2. 同名地区或地点有多个真实候选时，先用用户提供的上级地区、当前地图或明确上下文缩小；仍不能唯一确定时展示可识别的选项。
3. 对于行政区，点位优先使用 `district_adcode`，辅以点与边界的空间关系；路段基于完整轨迹与边界关系判断，不能只检查起点。
4. 在可获得有效边界时，区分“起点位于区域内”“轨迹穿过区域”和“仅在附近”，必要时计算区域内的轨迹长度或比例。跨界路段保留实际关系，不笼统标成全程位于该区。
5. 边界不可用时，可以使用具有来源的中心点与明确半径进行近似搜索，但结果只能称“附近”，不能当作严格行政区内结果。地点解析失败、数据库没有匹配和上游服务不可用分别返回不同状态。

所有参与比较的坐标先统一坐标系；实际接入地图服务前核实其坐标系、权限与覆盖范围。区域中心是搜索参考，不自动假定它本身可骑行或能够体现“在区域里骑一圈”。

### 路段和点位名称

对名称或类别执行分层检索：

1. 精确名称和稳定 ID。
2. 经过大小写、空白、标点等标准化的名称；经来源确认的别名、常见写法和中英文名称。
3. 有界的名称片段、分词或近似查询，结合已确定地域和类型；SQL 参数化并正确转义通配符。
4. 根据区域内的真实路段几何、真实点位或地图可验证地点，寻找相关候选。不同名称的附近结果标记为“相关候选”，不能自动断言就是用户所指对象。

候选按 ID 去重，排序考虑名称匹配、区域关系、用户偏好和已有标签；标签为 `unknown` 时保持未知。热门以已有热度数据或标签解释，不能凭常识列出“热门路段”。

模型可以生成多种搜索表达，但每条展示结果都必须映射到数据库或地图服务返回的真实记录；模糊匹配结果不得自动升级为精确匹配。大量候选时先使用索引或地域范围缩小，再做有界排序，避免无限扩大查询。

## 候选选择与会话状态

返回候选时保存稳定引用，至少包括 `id`、`type`、`name`、来源和展示顺序；将预算、体验、区域和已有约束一起保留。对于“第二个”“那个”“选某个名称”等回复，优先在最近展示的候选集中解析。

- 唯一匹配：复用已展示的候选 ID，按 ID 重新读取当前数据，再规划或回答。
- 多个匹配：展示足以区分的候选，询问用户选择。
- 未指明且只有一个适用候选：可选择该候选；多于一个时不擅自猜测。
- 记录已失效、改为私有或不再可用：说明原结果不可用，重新检索或请用户选择；不能静默切换到另一路段。

客户端带回的 ID 和上下文均为不可信输入。服务端必须检查 ID 格式、类型、与当前会话候选的对应关系，并重新查询权限和当前状态。实现时可选择服务端会话存储或经完整性保护的会话引用；多实例和过期恢复策略应与实际部署一致。

## 区域内骑行与前往区域

“搜索某区域有哪些路段”“从当前位置骑到某区域”“从当前位置去某区域并在当地骑一圈”是不同任务：

- **查询区域候选**：返回有证据的路段和点位；不将一次查询默认转换为已经完成路线规划。
- **前往区域**：以当前位置为默认起点和终点，选择区域内可导航的真实位置作为途经目标，调用骑行导航并验证实际进入该区域。
- **在区域内骑一圈**：从当前位置连接到区域后，在区域内构造和验证本地骑行段，再按需求返回。不能把“骑到区域中心后原路返回”直接描述为已在区域内绕圈。

如果区域内没有匹配的 Strava 路段，可基于区域内有坐标的真实点位与地图骑行导航构造候选；没有可用点位时，可由地图服务提供经验证可到达的地点。对多点环线，关键点的空间分布、路网连通、重复路段和地区内骑行范围都需要实际验证。连接失败时不生成虚构路径。

如果用户表示乘车到达地区后再骑，按其声明处理出发方式；否则保留从当前位置骑行的默认。区域较远或预算不足时，先用真实导航结果判断，说明往返距离与目标的冲突，并提供可直接选择的调整方式；不能把交通接驳或区域内起点当成用户已经同意的事实。

## 响应与失败语义

- 查询成功：给出真实候选及其来源、名称、可用属性和为什么符合已知偏好；只对有证据的内容作肯定描述。
- 名称无精确匹配但有相关结果：说明匹配不确定，展示名称及区域区别，不把它们描述为同一条路段。
- 已解析区域但库内无结果：说“当前数据中没有找到”，可以提出使用真实点位和地图导航规划，不说这个地区不存在。
- 地名歧义：请求选择具体地点或地区；输入提示返回多个结果不能默默选择第一个当成确定事实。
- 数据源不可用：说明检索暂时不可用，不把失败表示为零结果。
- 预算不满足：说明已尝试的范围和实际导航结果，允许用户更改预算、区域或出发方式。

## 推荐实现顺序与验收

1. 提取通用地域、路段和点位检索服务及来源、状态模型；覆盖不存在、无数据、服务故障和区域歧义。
2. 扩展 AI 意图与工具编排：事实检索先查后答；复合请求保留待规划需求与预算。
3. 为推荐结果保存稳定引用，完成按名称、序号和指代词选择；按 ID 重取并校验记录。
4. 接入边界和完整轨迹的空间关系；在边界不可用时明确降级到附近搜索。
5. 将区域约束和已选候选接入导航；实现区域内多点环线生成、候选比较与失败解释。

验收覆盖：存在精确路段、仅存在部分名称匹配、存在地点但无同名路段、候选被删除或变更、同名地区歧义、轨迹穿越区域但起点在外、边界缺失、地图服务故障、地区内无 Strava 但有真实点位、预算无法覆盖往返、用户按名称/序号/代词选择，以及多轮保留和修改预算偏好。

## 当前实现进度（2026-11-07）

已接入 LangGraph 的意图理解、条件检索和响应节点。具体地点咨询先检索公开路段及活跃点位；名称部分匹配与地点附近候选会标注不确定性。候选 ID、名称、类型和需求上下文随前端会话传回，选择时在公开数据中重新查询，未找到原记录时不会替换成另一个候选。用户明确重新开始时清除旧上下文。地图地点解析只接受唯一匹配，并支持唯一的行政区中心降级。

当前“附近”是以解析位置或地图中心为中心的近似范围，不是行政区边界查询；还没有实现区域边界与完整路段轨迹的空间相交，也没有构造或验证区域内部多点环线。选择行政区域规划时，结果会注明这一限制。包含起终点位置、候选以及预算的上下文暂由页面会话保存，不具备服务端持久化、签名防篡改或跨设备恢复能力。上述验收项仍需逐步完成。

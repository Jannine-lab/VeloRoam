# 骑行需求与路段多标签算法设计

状态：设计稿。需求默认规则已由用户确定；本文的分类阈值是 v1 初始建议，尚未对完整数据库完成校准。本文不代表分类、回填或对话流程已经上线。

## 1. 需求理解的输入与默认规则

用户未声明其他位置时，起点和终点均使用本次规划开始时的当前位置。一次规划固定同一份定位快照，避免计算过程中定位变化导致起终点漂移。用户明确指定的地点和结束方式覆盖相应默认值。

必须理解清楚的内容：

- 里程或时间预算：有一项即可；区分目标值、上限、区间。如果两项都有且无法同时满足，再追问优先级。
- 骑行目的与体验：例如轻松休闲、风景、爬坡训练、绕圈训练、长距离、热门路段；允许多选，出现明显冲突时再确认优先级。

未说清的必需内容才追问，已经在消息或历史中表达的内容直接复用。可以合并为一句：“这次想骑多少公里或多久？更想轻松看风景，还是爬坡、绕圈或骑热门路段？”这些选项只作为表达辅助，不限制自由回答。

必须经过、必须避开、车型、路面和出发时间等条件，用户未说时不阻塞规划。可附带一句“有特别想经过或避开的地方，也可以一起告诉我”，无需额外安排一轮必答问题。

定位不可用时先获取定位或让用户指定地点。用户给出时间预算时，用体验偏好对应的可配置速度范围建立初始距离搜索区间，再用实际路线估算时间校验；需要明确区分骑行时间和包含用户已声明停留的总时间。

预算示例：

| 用户表达 | 结构化结果 |
| --- | --- |
| 约 40 公里 | 目标里程 40；允许浮动另由明确的产品配置决定 |
| 不超过 40 公里 | 最大里程 40 |
| 30 到 40 公里 | 最小里程 30、最大里程 40 |
| 两小时内回来，喝咖啡半小时 | 总时间上限 120 分钟，已知停留 30 分钟 |

现有代码对只给目标里程的情况使用 ±50% 范围。该范围需要单独调整和明确展示，不能由模型悄悄选择。用户只指定新起点、未指定结束位置的组合，应在实施前明确采用“返回新起点”还是“仍回当前位置”，不在分类算法中隐式决定。

## 2. 分类对象与输出

分类对象是单条路段，初始六类标签为 `climbing`（爬坡）、`loop`（绕圈）、`out_and_back`（往返）、`long_distance`（长距离）、`popular`（热门）、`highly_starred`（高收藏）。六项分别评估，允许零个或多个命中。绕圈与往返使用互不重叠的整体形状条件，混合形态可以两项均不命中。

每个标签保留三种状态：

- `matched`：符合规则，对外出现在标签数组中。
- `not_matched`：有足够数据判断不符合规则。
- `unknown`：数据缺失、冲突或质量不足，暂时无法判断。

`tags: []` 可能表示六项均未命中，也可能有未知项；推荐服务需要读取评估状态区分这两种情况。未知不按零分或“不符合”处理，也不推断为相反属性。

分类使用确定性计算，模型消费已有标签和证据。名称只供检索和解释，名称中的“环线”“爬坡”等词不直接触发标签。

## 3. 特征提取与质量检查

当前可用字段包括完整路段轨迹、记录距离、平均坡度、最大坡度、累计爬升、爬坡类别、参与人数、尝试次数和收藏数。优先使用详情表的有效值，缺失时读取基础表中具有相同含义的字段，同时记录来源。

统一特征：

| 符号 | 含义 |
| --- | --- |
| L | 按所用轨迹顺序累加的长度，公里 |
| D | 轨迹首尾距离，米 |
| G | 来源字段中的累计爬升，米 |
| g | 平均坡度，百分数，例如 3 表示 3% |
| C | 爬升密度 G/L，米/公里 |
| A、E、S | 去重参与人数、尝试次数、收藏数 |
| R | 非相邻轨迹中反向近邻重走部分占总长度的比例 |
| M | 围绕一个候选折返点，去程与反向返程按顺序匹配后的长度覆盖率，取两侧覆盖率的较小值 |

处理规则：

1. 统一使用 WGS-84 坐标，检查有限值、坐标范围和单位。
2. 删除连续完全重复的坐标；保留骑行过程中再次经过同一位置的记录，以保留真实折返和多圈长度。
3. 原始轨迹长度用于总里程；按约 25 米等弧长重采样的轨迹用于形状分析。保留重采样前的转角顶点，避免切掉转弯。
4. 当有效源距离大于零，且 `abs(轨迹距离 - 源距离) / 源距离 > 20%` 时标记质量冲突；依赖精确长度的标签暂为 `unknown`，保留两种距离供检查。源距离缺失不自动判冲突。实际分布校准后再调整容差。
5. 明显断裂、点数不足或无法支持形状判断的轨迹，不输出肯定的绕圈标签。重采样不能补足原始数据没有提供的形状细节。
6. `G` 缺失时不使用最高海拔减最低海拔替代累计爬升；平均坡度为零也不能推出无爬升。

质量检查按标签依赖的字段生效。轨迹异常不必抹掉已有可靠人数数据得出的热门结论。

## 4. 六类标签的 v1 规则

以下数值均为待样本验证的产品阈值，不是通用行业标准。

### 4.1 爬坡

定义：具有达到一定长度和爬升量的持续上坡，或具有显著累计爬升密度、可用于爬升训练的路段。该标签包含有明显爬升的起伏或闭合路线，保留触发分支供推荐时细分。

满足任意一条即可命中：

1. 有效的来源爬坡类别在 1–5。
2. `L >= 0.5 km`，且 `g >= 3%`、`G >= 30 m`。
3. `L >= 2 km`，且 `G >= 80 m`、`C >= 20 m/km`。

第 2 条覆盖有一定长度的持续上坡，第 3 条覆盖平均坡度较低但累计爬升明显的起伏或闭合路线。短距离的单个最大坡度峰值不单独触发爬坡标签。

来源爬坡类别为 0 表示未分级，仍可通过自定义规则命中；类别数值越高表示更难，不直接将该数值当作用户熟悉的坡级名称。[Strava 字段定义](https://developers.strava.com/docs/reference/#api-models-DetailedSegment)

各条件按三值逻辑计算：有一条明确满足即命中；所有条件明确不满足才判未命中；仍有可能满足但缺少数据时为未知。规则中任一必要条件已确定失败时，该条规则即可失败，不要求额外补齐其他字段。

### 4.2 绕圈

定义：能够沿主体路径绕回出发附近，且主体去返路径不以反向重走为主的路段。标签描述几何形状，闭合缺口的实际可骑行性由路线规划层另外验证。

先检查闭合候选：

- `L >= 1 km`。
- `D <= min(150 m, 0.03 * L * 1000)`。
- 轨迹质量通过形状分析检查。

再排除原路往返：

1. 将轨迹按距离等权分析，为采样边计算约 50 米窗口内的方向。
2. 用空间网格索引查找非相邻边，初始近邻容差为 20 米。
3. 路程位置相差至少 100 米，且方向夹角至少 150 度的近邻边，记为反向近邻重走候选。对绕圈而言采用循环路程距离，避免把闭合处相邻的首尾误当作远离边。
4. 匹配时累计实际覆盖的子边长度，同一段轨迹只计一次；`R = 被反向匹配覆盖的轨迹长度 / 总轨迹长度`，命中要求 `R <= 30%`。

多次同方向绕圈不作为反向重走；交叉点附近少量近邻不应按整条边重复累加。双向平行道路可能被近邻算法混淆，因此 R 是几何估计值，要保存证据并抽样校准容差。已有道路拓扑或高程证据表明近邻边并非同一道路时，排除该匹配；无法区分的明显平行结构标记形状不确定，不强行判定。

此标签描述轨迹的环线特征。进入完整路线时，首尾缺口需要通过骑行导航验证；标签本身不证明缺口可以直接骑过。重复使用环线时，保留路段方向并验证接入点。

### 4.3 往返

定义：从出发附近沿一条主体路径去往远端，再沿大体相同的路径反向返回；不是所有“回到起点”的路段都属于此类。

命中需同时满足：

- `L >= 1 km`。
- 与绕圈相同的首尾接近条件：`D <= min(150 m, 0.03 * L * 1000)`。
- `R >= 70%`。
- 存在占累计路程 35%–65% 的折返位置，使两侧按相反方向进行有序轨迹匹配后 `M >= 80%`。

M 的计算：在候选折返点拆分轨迹为去程和返程，将返程倒序；在两条按约 25 米等弧长采样的序列上做单调有序匹配。可以使用最长公共子序列式动态规划，只有两点距离不超过 20 米时允许匹配，匹配索引必须递增且每个采样点最多匹配一次。分别计算两侧匹配长度占各自总长度的比例，取较小值作为该折返点的 M，再取各候选中的最大值。等距采样的点匹配按对应弧长单元计权，末端不足 25 米的单元使用实际长度。

M 用来排除多次杂乱折返或无序交叉造成的高 R。基础几何匹配可能混淆极近的平行道路，使用与绕圈相同的质量处理。

`30% < R < 70%` 的可靠轨迹视为混合形态，绕圈和往返都不命中，不为了覆盖率强行分类。

### 4.4 长距离

- 有可靠长度，且 `L >= 10 km` 时命中。
- 可额外保存 `10–<20`、`20–<40`、`>=40 km` 的距离档位供排序和解释。
- 标签描述完成这条路段轨迹所需的长度，包含轨迹里真实存在的多圈和折返；不描述整条推荐路线的总长度。

初始阈值的本地参考：`dev/strava-shanghai-z13-2026-11-03/candidates.json` 中有 2,553 个去重 ID，记录距离中位数约 1.796 km，P90 约 9.454 km，245 条不短于 10 km，100 条不短于 20 km。这是瓦片发现快照，不等于当前数据库或完整轨迹的校准结果。

### 4.5 热门

定义：在相同地域的骑行路段中，实际参与人数与骑行尝试规模均具有较高综合水平。与高收藏分别计算，收藏数不再进入热门公式；这替代了最初四标签草案中混合收藏权重的方案。

在同一城市的骑行路段中，为 A、E 分别建立有效值参考分布。每个分布至少 100 条；不足时逐级扩大至省级、全国，仍不足则为未知。所有热度指标统一使用满足样本要求的同一级地域，不混用城市人数百分位与全国次数百分位。参考集按路段 ID 去重，并对明显重合的路段版本做同方向几何聚类，避免重复版本主导分布；每组采用详情时间最新、并以 ID 打破并列的代表记录，不累加可能重复的人数。不按热门标签预先筛选参考集，保留真实零值。分布描述当前已收录路段中的相对位置，不等于城市全部道路的客观排名；样本量充足也不代表覆盖无偏。

各指标百分位使用中位秩，避免大量相同值被排到极高位置：

`Q(v) = 100 * (小于 v 的数量 + 0.5 * 等于 v 的数量) / 有效数量`

初始权重：去重参与人数 0.70、尝试次数 0.30。

`P = 0.70 * Q(A) + 0.30 * Q(E)`

命中条件：

- 去重参与人数已知，且 `A >= 50`。
- A、E 均已知，且相应参考分布足够大。
- `P >= 80`。

参与人数不足 50 时明确未命中；缺少指标时按三值逻辑保留未知，不能通过重新归一化把单个观测抬成高分。各个零值是有效观测，不能当作缺失。权重、人数下限和百分位阈值需通过样本校准。综合百分位分 80 不等同于综合排名严格处于前 20%。

这些字段表达累计参与和收藏状况，因此 v1 表达历史热门程度；没有时间序列时不生成“近期热门”。参与人数与尝试次数的含义以 [Strava 详细路段模型](https://developers.strava.com/docs/reference/#api-models-DetailedSegment) 为准。

### 4.6 高收藏

定义：在相同地域的骑行路段中，有较多用户收藏，体现关注或未来骑行意愿。此处描述收藏量，不将“收藏者占参与者比例”作为定义。

命中需同时满足：

- 可靠收藏数 `S >= 10`。
- 收藏数地域参考分布至少 100 条，使用与热门相同的参考集构建和地域回退规则。
- `Q(S) >= 90`。

S 小于 10 时明确未命中；S 缺失或参考分布不足时未知。不用 `S/A` 直接判定，以免少量参与者放大比例；收藏与参与不是同一人群漏斗，比例也不应被当作转化概率。

热门衡量实际参与，高收藏衡量收藏量；二者可以同时命中，也可以只命中其中一项。10 次收藏和百分位 90 是待验证的初始配置。

## 5. 存储、回算与接入

建议新增独立评估表 `strava_segment_tag_evaluations`，每个路段、每个标签保存一行当前结果：

```text
segment_id + tag                  联合主键
status                            matched / not_matched / unknown
reason_codes                      判定或缺失原因
evidence                          使用的原始特征、计算值与阈值
algorithm_version                 规则版本
reference_version                 热门参考分布版本，可为空
source_fingerprint                输入特征指纹
source_fetched_at / calculated_at  来源时间与计算时间
```

对外 `tags` 从 `matched` 行生成；保留完整评估供推荐服务解释和处理未知值。若需要审计历史，再增加按运行批次保存的结果记录。

现有 `strava_segment_recommendations` 已预留 loop、climbing、long_distance、leisure 四项评分，尚未定义完整模型。标签算法不将命中状态机械写成这些评分，也不覆盖现有 `raw_score`。热门标签使用独立热度特征；休闲适合程度后续需要路面、连接路线和其他体验依据再设计。

回填流程：

1. 读取已有基础表、详情表和完整几何，先生成特征预览，不发起额外外部详情请求。
2. 固定一版热门参考分布，确保同批结果可复现。
3. 生成六类标签的命中率、未知率、质量冲突报告，以及边界样本和地图预览。
4. 人工检查环线/原路往返、短坡、长距离、热门、高收藏及指标缺失样本，调整配置后重新预览。
5. 按确定的算法版本执行幂等回填，六类标签的三种状态均写入，重算时可以移除已不符合规则的旧标签。
6. 详情或轨迹更新时按指纹增量重算；热门参考分布变更时整体重算依赖它的结果。
7. 推荐接口返回标签和必要证据，agent 将它们作为候选匹配依据之一。

私有和明确危险等推荐过滤继续独立执行。热门、长距离或爬坡标签不抵消这些过滤。

## 6. 推荐时如何使用

先满足用户的明确限制，再结合体验偏好对候选加权：

- 爬坡训练：提升爬坡候选的匹配度，结合 G、C、g 判断强度。
- 绕圈训练：优先环线候选，结合单圈长度和预算决定使用方式；实际圈数和闭合性需规划层验证。
- 长距离：提高连续长路段的匹配度，仍按完整连接路线校验总预算。
- 热门路线：提高热门候选匹配度，保留参与人数、参考区域和数据时间等解释依据。
- 高收藏：作为关注度补充信号，与热门的权重分别配置。
- 往返路线：在用户希望熟悉返程路径时提高匹配度；不将它当作绕圈候选。
- 轻松休闲：综合已知坡度、爬升与用户预算；没有爬坡标签不能自动推出适合休闲。

多偏好按用户优先级组合，不强制要求同时命中所有标签。最终路线还需检查真实导航里程、时间、连接成本和重复道路比例。

## 7. 实施时的验收样本

| 样本 | 预期 |
| --- | --- |
| 数据可靠但不满足六项阈值 | 零标签，各项为未命中 |
| 几何缺失，人数和次数充足且热门 | 仍可有热门标签，绕圈未知 |
| 短距离最大坡度很高，累计爬升很小 | 不因最大坡度单项命中爬坡 |
| 平均坡度接近零，累计爬升和密度明显 | 可通过累计爬升规则命中爬坡 |
| 首尾接近、R 为 95%、有序反向匹配覆盖率 95% 的原路往返 | 命中往返，不命中绕圈 |
| 首尾接近、R 为 50% 的混合形态 | 绕圈和往返均未命中 |
| 同方向重复两圈 | 可以命中绕圈；距离计入两圈 |
| 轨迹名含“环线”，实际未闭合 | 不因名称命中绕圈 |
| 高 raw_score 但人数数据缺失 | 热门未知 |
| 人数、次数、收藏均为 0 | 热门未命中 |
| 12 km 的热门爬坡环线 | 可同时命中爬坡、绕圈、长距离、热门；收藏条件满足时再加高收藏 |

# Agent 骑行路线规划可靠性检查（2026-11-14）

## 已发现并修复

- 名称检索原先先按热度截取，再在应用层按名称排序。像较长的英文路段名，其末尾片段可能匹配大量记录，使低热度的精确名称在截取时消失。现在数据库先按完整名称匹配排序，再截取结果；三条此前遗漏的公开路段通过真实数据库重新检查均可检索到。不能据此断言这就是用户截图中那次路线连接失败的直接原因。
- 用户确认已选路段或地点后，直接根据已展示的 ID 重新读取当前公开记录；不再重复执行广泛名称查询和地点解析。记录失效时提示重新选择，不用相似名称替换。
- 骑行导航对网络超时、连接中断、HTTP 429/5xx 和明确可短暂重试的高德 QPS/服务忙状态，最多额外重试一次。按分钟或日限制、额度耗尽、参数错误、无道路和超过距离限制等状态不做无意义的快速重试。
- 同一轮候选路线比较最多同时构建三条，并对相同起终点的导航请求复用本次请求的结果，减少重复调用。
- 候选规划失败时保留不含坐标、名称、URL 或密钥的失败类别；对连接端点不匹配、预算不符、服务限流、额度不足、覆盖范围、无路线和暂时不可用等情况给出不同提示。原有的 100 米轨迹连接限制未放宽。

错误码归类参考[高德 Web 服务错误码说明](https://lbs.amap.com/api/webservice/guide/tools/info/)。

## 真实数据源重放

使用固定的测试出发坐标和公开路段“银港路至太海汽渡沿江骑行”，通过本机接口、真实模型、数据库和高德骑行导航连续重放三次“确认，开始规划”；三次均生成完整路线，距离约 151.4 公里，接口总耗时分别约 10.1、10.8、8.7 秒。路线构建包含现有的轨迹端点与预算验证。

上述只是**一个位置、一条路段的三次样本**，不能作为一般稳定性、时延或实际道路可骑行性的保证。截图中的原始失败因旧代码丢弃了底层失败原因，不能事后确定其具体错误；后续失败会保留不含敏感位置的类别，便于定位。

## 回归

后端自动化测试覆盖瞬时失败后重试、拒绝或额度错误不盲目重试、限流与无路线区分、100 米连接检查、候选并发限制、重复导航请求复用、精确名称检索，以及用户确认后按 ID 刷新和失效提示。构建和测试结果以本次实际执行为准。
